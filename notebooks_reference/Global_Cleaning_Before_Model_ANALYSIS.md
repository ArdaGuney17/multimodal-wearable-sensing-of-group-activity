## Function / class definitions

- **cell 1**, function `find_elan_file(group)` — globs `*Group_{group}*individual*build*renamed*.csv` under the group folder, filters out anything with "backup" in the filename, returns the shortest-path match (or `None`).
- **cell 2**, function `normalize_single_label(label)` — cleans one atomic label token: strips whitespace, replaces Turkish `ı`/`İ` with ASCII `i`/`I`, collapses internal whitespace to `_`, strips leading/trailing `_;,.`, collapses repeated `_`, then looks the result up in `GLOBAL_LABEL_REPLACEMENTS` (twice — once before and once after a second cleanup pass, since the dictionary lookup can itself reveal a further typo to fix).
- **cell 2**, function `normalize_label_cell(cell)` — handles a full cell value that may hold multiple labels joined by `+` or `|`; splits, normalizes each atomic part via `normalize_single_label`, deduplicates, and rejoins with `" + "`.
- **cell 2**, function `path_score(path, group, sensor)` — heuristic ranking score (lower = better) for candidate input files: heavy penalties for `model_ready`/`summary`/`labeling_summary` (+10000) or `backup` (+5000) or `old` (+1000) in the path; bonus (−100) for `labeled`/`labelled` in path; bonus (−50) for sensor name or `group_{group}`/`group{group}` in path; extra sensor-specific bonuses/penalties (e.g. optitrack: −1000 for the canonical `group_{group}_optitrack_labeled.csv` filename; openearable: +100 penalty if `acc`/`accelerometer` appears, since raw accel files are less likely to be the final labeled file); tie-break by shorter path length.
- **cell 2**, function `find_labeled_file(group, sensor)` — builds sensor-specific glob pattern lists, globs them all, dedupes, keeps only `.csv`, hard-excludes anything containing `model_ready`/`summary`/`labeling_summary`/`all_elan_unique_labels` in the filename, then sorts remaining candidates by `path_score` and returns the best one plus the full sorted candidate list.
- **cell 2**, function `get_label_columns(df)` — returns `[c for c in df.columns if c.startswith("label_")]`.
- **cell 2**, function `clean_label_columns(df)` — applies `normalize_label_cell` to every `label_*` column; returns the cleaned df plus the `before`/`after` sets of unique atomic label values (for the before/after reporting CSVs).
- **cell 2**, function `trim_to_labeled_range(df)` — finds the first and last row index where *any* `label_*` column is non-empty; slices the dataframe to that inclusive range; returns the trimmed df, `first_idx`, `last_idx`, and counts of rows removed before/after.
- **cell 2**, function `add_model_ready_metadata(df, group, sensor, source_path, first_idx, last_idx)` — adds `model_ready_group`, `model_ready_sensor`, `model_ready_source_file` (basename only), `model_ready_trim_first_original_row`, `model_ready_trim_last_original_row` columns.
- **cell 2**, function `get_time_info(df)` — for a fixed candidate list of time-column names (`video_time_s`, `time_s`, `time`, `timestamp`, `timestamp_s`, `elapsed_time_s`, `seconds`), returns `{col}_min`/`{col}_max` for whichever columns are present and have at least one numeric value.
- **cell 3**, function `get_candidate_patterns(group, sensor)` — returns a short list of broad (unfiltered) glob patterns per sensor, used only for the fast informational listing.
- **cell 3**, function `detect_flags(path)` — scans the lowercased path/filename for a fixed keyword list (`labeled`, `labelled`, `shifted`, `sync_peak`, `last10_peak`, `clap`, `early_peak`, `cleaned`, `gap_flag`, `merged`, `continuous`, `model_ready`, `backup`, plus `summary` in the basename) and returns a comma-joined string of the ones found — purely descriptive, for the human reviewing the candidate table.
- **cell 3**, function `inspect_csv_header_only(path)` — reads only the first 5 rows of a CSV (fast) to report file size, column count, `label_*` column count/names, presence and min/max of known time columns; wraps everything in try/except and records the error string on failure.
- **cell 4**, function `normalize_single_label(label)` — **re-implementation of cell 2's function, but against a different (smaller) `GLOBAL_LABEL_REPLACEMENTS` dict** — see Hyperparameters/Broken-cells sections.
- **cell 4**, function `normalize_label_cell(cell)` — same logic as cell 2's version, calling the cell-4-local `normalize_single_label`.
- **cell 4**, function `get_label_columns(df)` — identical to cell 2's.
- **cell 4**, function `collect_unique_labels(df, label_cols)` — new helper (cell 2 inlined this logic instead of factoring it out): walks the given label columns, splits each non-empty value on `+`/`|`, and returns the set of unique atomic label strings.
- **cell 4**, function `clean_label_columns(df)` — same shape as cell 2's, but calls `collect_unique_labels` before/after normalization instead of inlining the loop.
- **cell 4**, function `trim_to_labeled_range(df)` — identical logic to cell 2's.
- **cell 4**, function `get_time_info(df)` — identical logic to cell 2's.
- **cell 4**, function `add_model_ready_metadata(df, group, sensor, source_path, first_idx, last_idx)` — near-identical to cell 2's, but **also adds `model_ready_source_path` (the full path, not just the basename)**, which cell 2's version does not.
- **cell 5**, function `get_expected_path(group, sensor)` — builds `{BASE}/group_{group}/{sensor}/model_ready/group_{group}_{sensor}_model_ready.csv`.
- **cell 5**, function `get_time_range(df)` — like `get_time_info` but always emits `{col}_min`/`{col}_max` for every known time column present (using `np.nan` when there's no numeric data), rather than omitting the column entirely.
- **cell 5**, function `label_coverage(df, label_cols)` — returns `(count_of_rows_with_any_nonempty_label, percent)`.
- **cell 5**, function `collect_unique_labels(df, label_cols)` — third re-implementation of the same helper (functionally identical to cell 4's).
- No functions in **cell 6** (one-off script) or **cell 7** (straight copy loop).
- **cell 8**, function `detect_coordinate_prefixes(df)` — finds column-name prefixes with an `_x`/`_X` suffix (skipping `label_*`/`model_ready_*` columns) that also have a matching `_y`/`_Y` or `_z`/`_Z` sibling column; returns the sorted list of such prefixes (these are OptiTrack's raw rigid-body/marker names, e.g. auto-numbered rigid bodies that don't inherently map to Participant1/2/3).
- **cell 8**, function `get_x_col(df, prefix)` — returns whichever of `{prefix}_x` / `{prefix}_X` exists in the dataframe.
- **cell 8**, function `infer_left_middle_right_robust(df, prefixes, search_rows=100000, valid_sample_rows=5000)` — for each of the (expected 3) coordinate prefixes, finds the first row within the first `search_rows` rows with a non-NaN x value, then averages the first `valid_sample_rows` valid x-values as that landmark's representative x position; sorts the 3 prefixes ascending by that mean x to assign physical `"left"`/`"middle"`/`"right"` labels; raises `ValueError` if it doesn't end up with exactly 3 valid prefixes.
- **cell 8**, function `build_prefix_rename_map(position_to_prefix, participant_position_map)` — composes the group's `PARTICIPANT_POSITION_MAP` entry (which participant sat where) with the just-inferred `position_to_prefix` mapping to build `{raw_optitrack_prefix: "ParticipantN"}`.
- **cell 8**, function `rename_optitrack_feature_columns(df, prefix_to_participant)` — renames every non-`label_*` column whose name either equals a raw prefix or starts with `{prefix}_` so the prefix becomes `ParticipantN` (or `ParticipantN_<suffix>`); returns the renamed df plus the actual rename map used.
- **cell 8**, function `check_canonical_labels(df)` — returns `(all_label_cols, missing_canonical, extra_non_canonical)` against the fixed 7-column `CANONICAL_LABEL_COLS` list (refactor of the inline check duplicated in cell 5).

## Potentially broken / disabled cells

- **Duplicated + diverging `GLOBAL_LABEL_REPLACEMENTS` dictionaries (cell 2 vs. cell 4)**: cell 2's dictionary (~210 entries) is materially larger than cell 4's (~150 entries). Because cell 4 is the one whose output actually survives (same output path as cell 2, run later, manually curated `SELECTED_FILES`), several typo-correction rules that exist in cell 2 are **silently absent** from the label cleaning that ends up in the shipped `model_ready` files. A future port should treat **cell 4's dictionary as the ground truth**, but flag this loss of coverage to a human — it's unclear whether the omissions in cell 4 were deliberate trims or just copy-paste drift.
- **Cell 2's automatic pipeline is fully superseded, not deleted**: cell 2's `find_labeled_file`-driven main loop writes to the exact same output paths that cell 4's manually-curated `SELECTED_FILES` loop writes to afterward. If cell 4 is run after cell 2 (as the cell ordering implies), cell 2's work is completely overwritten. Cell 2 is best understood as an earlier, automatic-but-unreliable attempt that cell 4 replaces with hand-picked files — not unlike a "dead" branch, except it does real work and real I/O before being overwritten, so re-running only cell 2 without cell 4 would leave the "wrong" (auto-selected, not human-verified) files in place.
- **Cell 3 does not gate anything programmatically** — it's explicitly commented "This DOES NOT process files," purely informational, meant to be read by a human to build `SELECTED_FILES` in cell 4. There is no assertion tying `SELECTED_FILES`'s literal paths back to cell 3's candidate list, so if source files were renamed/moved, cell 4 would simply hard-fail with "file does not exist" per missing entry (handled gracefully — logged to `missing_or_skipped`, not a crash) rather than through any check against cell 3.
- **Cell 6 is a hardcoded, group-1-only, xsens-only patch** applied *after* the main pipeline (`FIX GROUP 1 XSENS EXTRA LABEL COLUMNS`), evidence that the cell-5 sanity check found group 1's xsens model-ready file carrying stray non-canonical `label_p1`/`label_p2`/`label_p3` columns (likely a leftover naming convention from an earlier stage of the xsens labeling process for that one group). It directly overwrites the model_ready file in place. This is a genuine group-specific special case, not something the general pipeline (cells 2/4) guards against — if a similar issue exists in another group/sensor, it would not be caught or fixed automatically; cell 5's sanity check would flag it (`status = "missing_canonical_label_cols"` or `"has_extra_label_cols"`) but nothing then auto-repairs it except this one hand-written cell targeting exactly `group_1`/`xsens`.
- **Cell 8's OptiTrack identity fix silently degrades to "copy unchanged" on failure**: if `detect_coordinate_prefixes` doesn't find exactly 3 valid prefixes, or `infer_left_middle_right_robust` raises (e.g., column count mismatch, no valid data in the search window), the `except`/`if len(prefixes) != 3` branches log a warning and a `status` value (`"optitrack_prefix_detection_failed_copied_unchanged"` / `"identity_fix_failed_copied_unchanged"`) into `IDENTITY_FIXED_manifest.csv`, then fall back to `shutil.copy2` of the **un-fixed** file. This means it's possible for a group's `optitrack` file to land in `ALL_MODEL_READY_FILES_IDENTITY_FIXED/` **without actually having its participant identity corrected**, and the only way to know is to inspect the manifest CSV's `status` column — nothing else surfaces this. Anyone consuming these files downstream should verify the manifest shows `"identity_fixed"` for all 9 groups' optitrack rows before trusting the `ParticipantN_*` column names.
- **Cell 1 (`INSPECT ALL ELAN LABELS ACROSS GROUPS`) is a standalone diagnostic, disconnected from the rest of the notebook's data flow**: it reads raw positionally-indexed ELAN export CSVs (a different, upstream file convention: `*Group_{group}*individual*build*renamed*.csv`, read with `header=None`) to enumerate every unique atomic label ever used, and its only output (`all_elan_unique_labels_for_cleaning.csv`) is not read by any later cell in this notebook. ## Summary

This notebook is the bridge between per-sensor, per-group *labeled* CSVs (already synchronized/time-shifted and already carrying ELAN-derived `label_*` columns — evidently produced upstream by other notebooks not included here, given filename suffixes like `_shifted_by_clap_sync_peak.csv` and `_SHIFTED_EARLY_PEAK.csv` baked into `SELECTED_FILES`) and a single, cleaned, canonically-named, per-group/per-sensor "model-ready" corpus. **Exact expected inputs**: for each of the 9 groups (`GROUPS = [1,2,3,5,6,7,8,9,10]`, group 4 is never present in this project) and each of 3 sensors (`openearable`, `xsens`, `optitrack`), one specific already-labeled CSV, hand-selected in the `SELECTED_FILES` dict of cell 4 (superseding the automatic-glob-based selection attempted in cell 2) — each such input file already has raw sensor feature columns (per-sample, not windowed — OptiTrack rows carry `{prefix}_x/_y/_z` per-sample coordinates, not aggregated window statistics) plus 7 canonical `label_*` columns (`label_Participant1/2/3`, the 3 pairwise combinations, and `label_Whole_Group`) already attached and already time-corrected for cross-sensor sync. **"Global cleaning" here means three concrete, code-verified operations, applied independently per (group, sensor) file — never merging sensors together**: (1) normalizing the *text* inside the `label_*` cells — fixing hundreds of typo/spelling/language variants of the same underlying activity label (e.g. `"synchronaziton_move"`, `"synchronizaiton_move"` → `"synchronization_move"`; Turkish `ı`/`İ` character slips; inconsistent underscore/space/punctuation usage) via the `GLOBAL_LABEL_REPLACEMENTS` dictionary and `normalize_label_cell`/`normalize_single_label`, with combined `"A + B"` labels split, individually normalized, deduped, and rejoined; (2) trimming each sensor file down to the row range that actually has any label at all (`trim_to_labeled_range`, dropping unlabeled rows before the first labeled row and after the last); and (3) — the final cell, and the one that actually creates the target directory — a **participant-identity fix for OptiTrack only**: OptiTrack's raw motion-capture export numbers its 3 tracked rigid bodies/markers by an internal, per-session-arbitrary prefix that does not consistently correspond to Participant1/2/3 across groups (because different groups' three participants sat in different left/middle/right physical arrangements), so `infer_left_middle_right_robust` infers each raw prefix's physical left/middle/right position from its mean x-coordinate over the first several thousand valid samples, and `PARTICIPANT_POSITION_MAP` (a hand-curated seating chart, one entry per group) is used to translate physical position back to `ParticipantN`, after which every `{prefix}_*` feature column is renamed to `ParticipantN_*`. **This identity fix touches only OptiTrack feature (coordinate) columns — it never touches the `label_*` columns or the openearable/xsens data**, which are assumed to already be correctly participant-attributed from the ELAN annotation stage and are simply copied through unchanged. **"Model-ready" as an output format** is therefore *not* windowed at all: each output row is still one original sensor sample (whatever the native sampling rate of that sensor was — no resampling, no aggregation, no fixed-length window construction happens in this notebook), with columns = original per-sensor feature columns (renamed for optitrack) + the 7 canonical `label_*` columns + housekeeping metadata columns (`model_ready_group`, `model_ready_sensor`, `model_ready_source_file`, and in cell 4's version also `model_ready_source_path`, plus `model_ready_trim_first_original_row`/`model_ready_trim_last_original_row`). This directly contradicts the task's framing premise that this notebook runs *after* per-group windowing — based on the actual code, no windowing (5s/10s segment aggregation, the kind referenced by filenames like `binary_5s_all_sensor_advanced_features.csv` in the Task 1 notebook) happens here; that must be a separate, later feature-engineering step (likely inside `Arda_Thesis_Data_Preprocessing_FIXED_v4.ipynb` or an unincluded notebook) that consumes exactly the files this notebook produces as its raw per-sample input. **The pipeline is uniform across all 9 groups in structure** (same code runs for every group/sensor pair in a loop) **but has three explicit sources of group-specific special-casing**: (a) `SELECTED_FILES`, where the literal input path per group/sensor encodes which upstream sync-correction variant was chosen for that specific group; (b) `PARTICIPANT_POSITION_MAP`, a fully bespoke left/middle/right seating assignment per group, required for the OptiTrack identity fix to work at all; and (c) cell 6, a one-off patch that drops stray `label_p1/p2/p3` columns found only in group 1's xsens file. **For porting into `src/preprocessing/`**: preserve the exact `GROUPS`/`SENSORS` lists and treat cell 4's (smaller, ~150-entry) `GLOBAL_LABEL_REPLACEMENTS` dict as canonical over cell 2's (larger, ~210-entry) one, but surface the diff to a human since it looks like accidental drift rather than an intentional trim;
