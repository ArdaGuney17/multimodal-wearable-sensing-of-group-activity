What's genuinely proven

Raw sensor sync, all 9 groups, both sensor families

OpenEarable + Xsens (video-time alignment, sync-move peak-shift, label attachment) and OptiTrack (raw unstable marker tracks → stable participant identities, via hand-curated per-group/per-take allowlists, not the algorithmic Hungarian-tracker dead ends the source notebook explored and abandoned) are exact for every group that has a recording. Group 4 is permanently excluded — camera failure during recording, a genuine data limitation, not a reproduction gap.

Task 1 features (5s windows): 26/26 group×family combinations exact

True raw sensor files, through this repo's own sync/clean/feature code, reproduce the official OpenEarable, Xsens, and OptiTrack feature tables bit-for-bit — for all 9 groups, zero dependency on any pre-computed intermediate file.

Task 3 tokens and their label input: all 9 groups exact

The 6-label activity-token generation matches the official token table exactly (244 tokens across all groups). Its own input — a label-normalization step that was previously only reconstructed circularly (extracting columns back out of its own target file) — was rebuilt for real from raw ELAN data this sprint: 0 mismatches on every downstream classification column, all 9 groups.

Table 8.7 — the thesis's own headline Chapter 8 result

All 7 n-gram/HMM/hybrid grammar models reproduce exactly, including a documented reproducibility trap in the source notebook (token group column must be treated as text, not int).

Data hosting and provenance

Anonymized per-group archives built and published (interim: public Drive folder; Zenodo once the paper is out), with an allow-list — not deny-list — safety model so an unknown future file can never slip a real name through. SHA-256 checksums recorded for every file.

GAPS

What's still missing

The one-command pipeline script isn't wired up

scripts/reproduce_pipeline.py — the actual polished tool meant for someone else to run — has none of this sprint's fixes in it. Every proof above lives in ad-hoc scripts under data/external/thesis_data/END_TO_END_PROOF/, gitignored, built to prove a point rather than to be a product. Getting from "we proved it's possible" to "run one command and watch it happen" is real, undone work.

The model-training layer was only stress-tested for Task 1

We proved reconstructed features → identical model results is almost true for Task 1 (see the gap below). That exact test — feed our own reconstructed data into the real model code and diff the output — was never repeated for Task 2's classifiers or Task 3's downstream models (Tables 8.2–8.8). Those tables were validated against the official feature files, not against our own reconstructed ones.

Two small, precisely-diagnosed residuals in Task 2

Groups 2 and 8 have one feature family (OE10 magnetometer stats) that's provably correct but inherently float-boundary-fragile in the original notebook's own methodology — not fixable without recovering a one-time Colab execution's exact float64 state. Group 10 has a small, unresolved data-completeness gap (9 missing samples out of ~10,500 in a reconstructed Xsens stream).

No automated regression suite

Every validation this sprint ran as a one-off script, executed once, read once. There's no pytest-style suite that would catch a future change silently breaking something already proven — the proof exists in the git history and docs, not as a repeatable check.
